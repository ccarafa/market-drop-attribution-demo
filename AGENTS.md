# Project rules

Use neutral aliases only in records. Do not write personal names, identity mappings, credential contents or identity-bearing local paths.

The user authorized a real-data website update on 2026-10-15 using existing local data, after the new provider's full delivery proved unavailable. The default homepage is a retrospective daily evidence study of the local July 2026 data: 5,210 stock codes, 23 dates, and 119,652 stock-days. Preserve the actual limited date coverage; the requested latest-year scope remains a future data requirement. Do not join the provider's limited 2025 exports to 2026 events. Do not fetch AWS or restart completed research work.

Since 2026-10-28 the `demo.html` intraday replay no longer contains invented reasons: on the user's explicit request every triggered event shows the stock-day's end-of-day attribution (same method as the homepage; no probabilities when the day's return stays within 2%) together with the real announcements, company and industry articles and macro context from `data/replay_evidence.json`, each with its publication time and source link, split into "known before the crossing bar" and "disclosed afterwards" by `eventEvidence`, plus trading facts from the five-minute bars (`barFlow`) and the daily aggregates. Keep that as-of split, the time stamps and the links; never present the end-of-day probabilities as intraday predictions or causal findings, and never add fictional content back. Rebuild the pack with `python tools/build_replay_evidence.py --daily <parquet> --evidence <dir>` after rebuilding the attribution data.

Real-data output reports measured returns, a clearly labeled sample comparison, historical volume/spread baselines, missingness and price-reference diagnostics. These are descriptive evidence, not causal estimates or reason probabilities. Full-day observations are retrospective and cannot be represented as information available intraday. Only earlier observations may form historical baselines; incomplete history remains missing. The source's final snapshot price is not independently confirmed as the exchange close. No news, historical industries or corporate-action validation has been added.

For the retained Demo, only finished five-minute close observations trigger events. Default basis is current close relative to the highest previously completed close of the same day; alternate basis is reference previous close. Strict decline greater than 5%, with 1e-12 tolerance. Emit when crossing the threshold, not on every bar that remains below it. A recovery permits a new crossing. The next-event navigation is retrospective case selection, not prediction. The real-data homepage uses the separate daily event definition documented in docs/REAL_DATA_METHOD.md.

Use relative static paths for GitHub Pages. Do not add server authentication to a public static page. Never commit .runtime/, accounts, keys, raw archives or unrelated market data.

The user requested official DataYes API integration on 2026-10-15 and has contacted the provider; the reply is pending. Connection tooling is prepared, but no authenticated business response has been verified and no official API financial records have been published. Keep this distinction explicit. Use DATAYES_API_TOKEN as an encrypted repository Secret or private process environment variable, never a workflow input, public variable, command-line argument or source constant. The manual DataYes connection check is bounded to one request, one date and one ticker; it does not activate a schedule, publish prices or certify complete market coverage. Confirm actual API product/token compatibility, historical entitlement, billing, pagination/IP rules and public display/export scope before expanding the request or publishing provider records. Details are in docs/DATAYES_CONNECTION.md.

The user requires browser exploration in the background. Do not foreground browser windows, switch the user's active tabs, or send keyboard/mouse input. Use public HTTP requests or an isolated headless browser; if authentication cannot be reused safely in the background, request the specific configuration instead.

Since 2026-10-28 the homepage `index.html` is the attribution workbench built by `tools/build_attribution.py` from the local daily aggregates plus private provider evidence metadata (announcements and finance-article titles, times and links; never full texts). Its probabilities are in-sample associations: attributable fraction 1 - 1/LR per direction-consistent feature, features below the minimum likelihood ratio listed but not credited, market and industry shares from same-sign fractions, and a trading-flow fallback so every event has a stated reason. Keep that wording; never describe the probabilities as causal, validated or predictive. The former evidence workbench stays at `evidence.html`. Rebuild with `python tools/build_attribution.py --daily <parquet> --evidence <dir> [--moneyflow <dir>] [--intraday <parquet>]`; the evidence directory, the provider money-flow files and credentials stay outside the repository. Money-flow features (main = large + extra-large orders, thresholds as shares of turnover) describe order sizes only; never call them institutional or retail identities. Taxonomy changes go in `tools/attribution_taxonomy.py` with tests in `tests/test_attribution.py`.

Run `npm test`, `python -m unittest discover -s tests -p 'test_*.py'`, `python tools/check_attribution_browser.py`, `python tools/check_real_browser.py`, `python tools/check_browser.py`, then `python tools/validate.py` for material data/UI changes. Pass the actual HTTPS root URL to browser checkers to verify publication; the legacy checker targets `demo.html`. Browser/runtime records stay ignored. Publishing must derive the existing target from origin, verify the authorized credential and repository push permission, use an explicit file allowlist, and never create or change an unrelated repository.
